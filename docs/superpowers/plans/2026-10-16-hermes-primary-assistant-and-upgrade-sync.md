# Haitlify：Hermes 主助手重建与首版闭环计划

**版本：Draft v5，补齐 v4 条件复核意见；v5 尚待独立复核。**
**日期：2026-10-16。**
**状态：路线与首版业务闭环已确认；尚未实施。文档通过不等于运行验收通过。**

## 1. 已确认的产品决策

1. 在 `fy-github/Haitlify` 新仓按新架构重建，工作分支为 `feat/hermes-ai-assistant`。可以删除旧自研 AI 和重构 UI；不改旧归档仓库，不另开第三个仓库。
2. Hermes 承担完整 AI 助手：理解、多轮对话、规划、工具选择、模型调用、澄清和任务编排。不是某一个后台生成步骤。
3. Haitlify 承担业务宿主：身份权限、需求和资产、人工确认、脚本验证、受控执行、证据、报告、审计。不得在 Bridge/MCP 内重新建设 Agent Loop。
4. 不要求旧数据、旧页面、旧 API 兼容；不保留旧 Agent 的手动/自动回退。Hermes 不可用时明确报不可用。删除代码的授权不等于清空旧数据库或运行资源的授权。
5. Haitlify 使用自有全局助手 UI，服务端代理 Hermes，浏览器只登录 Haitlify；不嵌入官方 Dashboard，不向浏览器暴露运行时管理凭据。
6. 首版必须完成：**需求 → 用例草稿 → 确认 → 页面探索与脚本 → Runner 实跑 → 报告**，以及恢复、隔离、升级验证。只读探针和单条闭环均为内部里程碑，不能作为首版签收。
7. Hermes 浏览器承担受控探索，正式回归由 Runner 执行经过验证和确认的脚本；二者能力和状态必须交接，不能靠共享 Cookie 偶然跑通。
8. 生产固定 Hermes stable/release 或对应不可变镜像 digest；自动发现/预验证，人工批准生产升级。不 fork Hermes，不许诺自动拥有每个官方 UI 功能。
9. 旧助手所有 QA 任务、外部 Jira/Confluence 写入不自动纳入首版。首版核心是上述测试闭环，不以“完整业务”无限扩大范围。

## 2. 成功不是换个聊天窗口

用户同时存在四类困扰，必须分别验收，不能互相抵消：

| 痛点 | 新系统必须证明 | 不能算成功 |
|---|---|---|
| 页面和需求都有，仍生成不出脚本或跑不通 | 来源明确的输入、页面证据、可执行动作、真实断言与报告 | 只生成用例、Locator 或 IR 文本 |
| 需求理解和覆盖差 | 冻结需求项/分支矩阵，逐项追溯、列遗漏和人工修改 | 模型自己声称覆盖完整 |
| 卡住、状态不可信、反复修复 | 任务状态分层、停止/恢复、UNKNOWN 对账和资源回收 | 心跳、HTTP 200、单测通过 |
| 配置复杂，手工操作比直接使用 Hermes 多 | 用户只提供目标、材料和必要确认；上下文和证据自动关联 | 要用户手工挑 Agent、复制 ID、逐阶段启动 |

Hermes 替换通用 AI 编排，不自动解决需求质量、登录状态、输入来源、动态页面、数据库事务和 Runner 缺陷。这些仍有确定的业务责任和测试。

## 3. 总体架构和事实归属

```text
Haitlify Web：对话 + 资产/差异 + 审批 + 执行证据 + 报告
    ↓ 已认证请求
Haitlify 服务端
    ├─ Bridge：协议、会话绑定、事件投影（无规划 Loop）
    ├─ 业务请求账本：受理、幂等、审计、UNKNOWN 对账
    └─ 版本化 MCP 业务工具：鉴权、校验、资产持久化
    ⇅ 受保护的官方协议 / 受信调用上下文
Hermes 服务：Agent、Provider、工具选择、澄清、对话历史
    ↓ 受控探索工具（行为策略强制执行）
探索证据 + 候选动作
    ↓ Haitlify 确定性验证/编译/人工确认
不可变脚本版本 + 执行交接包
    ↓
Runner：新隔离上下文、实际执行、断言、证据、清理
    ↓
Haitlify 结果和报告（事实统计 + 标注来源的 Hermes 分析）
```

| 事实 | 权威来源 | 禁止混淆 |
|---|---|---|
| 对话、运行中消息、工具交互 | Hermes | Haitlify 不维护第二套完整 Transcript |
| 用户/项目/授权、业务操作受理 | Haitlify | Prompt 或工具参数不能声明身份 |
| 需求、草稿、确认、脚本 revision | Haitlify | 聊天“同意”文本不是正式确认记录 |
| 执行步骤、断言、截图、清理状态 | Runner，Haitlify 校验并存档 | 助手最终回复不是运行成功 |
| 模型/工具原始来源与版本 | Hermes 调用证据 + 业务审计 | 规则提取不得标模型生成 |

Haitlify 保存 Session 绑定、业务请求账本、脱敏审计与业务资产，不复制对话作为第二个事实来源。账本只做确定性协调，不选择下一步策略、不自动补 prompt、不另建模型重试 Loop。

## 4. 用户流程与状态闭环

### 4.1 正常流程

1. 用户在当前项目提交目标及需求附件；服务端验证 context envelope，保存不可变来源版本。
2. Hermes 获取授权材料，发现缺项或歧义时集中澄清；原文事实、推断、待确认分开。需求不完整不得生成“已全覆盖”结论。
3. Hermes 经业务工具保存用例草稿、来源引用和覆盖矩阵；用户在资产卡查看差异并正式确认测试意图。
4. Hermes 用受控浏览器取证，生成候选动作；Haitlify 解析输入引用、校验证据、确定性编译并保存脚本版本。校验错误以结构化结果返回 Hermes，由 Hermes 决定修订，不在编译器中调用旧 AI。
5. UI 展示执行环境、脚本版本、输入引用、预期副作用和清理动作；用户确认，服务端生成绑定该版本的业务授权。
6. Runner 在新隔离上下文准备环境和身份，执行同一已确认脚本；持续输出步骤事实，失败有证据和分类。
7. 无论成功/失败/取消都执行清理；报告保留全体结果、未执行项和资源清理状态。Hermes 生成的诊断与 Runner 实测事实分开展示。
8. 用户可以追问和修订；需求/输入/脚本变更生成新版本并使相关旧确认失效。重跑是新的显式运行，不覆盖历史失败。

### 4.2 确认与易用性

- Hermes approval 是工具许可，Haitlify confirmation 是正式业务授权，两种语义不互相冒充。
- 草稿可在用户任务授权范围内保存，但正式入库/执行等动作需要业务确认。
- UI 可把待处理许可和业务差异放在一张卡中，必须分别记录动作与授权凭据；不为每个底层只读调用重复弹窗。
- 授权绑定用户、项目、对象 revision、动作、环境和输入 digest，有过期时间和撤销检查；旧审批、模型伪造或其他用户回包一律拒绝。
- 不要求用户手工复制 Session/Run/Evidence ID；只让用户处理真实决策，不承担内部编排。

### 4.3 失败、停止和恢复

明确区分：助手正在处理、等待用户、业务操作已受理、Runner 正在执行、测试通过/失败、执行异常、已取消、结果未知、清理未完成。

- 断开页面只是取消订阅，不默认取消服务端工作。
- 用户停止会同时请求停止 Hermes 当前执行和已关联的受控 Runner 工作；收到停止请求不立即显示已停止，等待各执行方终态与清理结果。
- Provider/工具失败不回退旧 Agent，不用模板伪造模型成功。
- 已发生的外部副作用不能因取消而假装撤销；报告保留并要求对账/补偿。
- 响应丢失或进程崩溃后，状态为 UNKNOWN；先用请求账本及真实目标回读对账。无法证明未执行时不得自动重发副作用。
- 业务失败报告也是有效交付结果，但不能伪装“测试通过”；验收中的预期故障注入与产品缺陷分开统计。

### 4.4 跨执行方状态与竞态裁决

状态分三条轴记录：执行事实、资源清理、报告接受。禁止用一个 completed 字段覆盖三种含义。执行事实由实际 Runner/目标业务回读决定，Hermes 终态只证明助手轮次结束；请求账本记录受理和关联，不能替执行方宣告成功。

| 竞态/异常 | 服务端裁决 | 用户下一步 |
|---|---|---|
| 取消请求与 Runner 完成同时发生 | 保留真实完成结果和取消请求时间；显示取消未阻止已完成动作，继续清理 | 查看结果，不自动重跑 |
| 请求回执迟到 | 核对 request/attempt/运行代次，归入同一账本；冲突事件保留审计并对账，不覆盖已有可信终态 | 查看更新后的状态 |
| 受理是否成功不明 | UNKNOWN，冻结该 operation 的副作用派发；查询 Hermes 可核验轮次和目标 operation | 继续对账或进入人工处置，不能无条件重发 |
| 恢复后 Session 绑定孤立 | 停用旧审批和游标；保存已确认业务事实，旧运行只读 | 有权限人员可新建会话关联旧报告，不伪造原会话恢复 |
| 已执行但无法确认结果 | 对账或人工补偿；未确认副作用不会因新授权消失 | 原 operation 完成对账/补偿或风险明确处置前，不允许重复执行同一业务动作 |

状态更新使用记录版本和执行代次校验；迟到的旧代次事件不能污染新运行。执行从受理→派发→运行→完成/失败/取消；UNKNOWN 只能经权威回读或有审计的人工处置解除。终态纠正保留前后记录，不抹掉失败。

## 5. Hermes 协议、身份和隔离

### 5.1 接入方式

首选 TUI Gateway JSON-RPC/WebSocket，经 Haitlify 服务端代理；具体能力按选定版本探针确认。API Server 同样运行完整 Agent 和工具，并非纯文本模型端点；不同时开发两套主协议。若 TUI 协议不可满足关键契约，暂停并提交协议选择变更，不暗中降级。

| 协议类别 | 示例 | 必须处理 |
|---|---|---|
| 客户端方法 | session.create/resume/history/status、prompt.submit、session.interrupt | 关联请求与结果，区分超时与明确拒绝 |
| 通知 | gateway.ready、message.delta/complete、tool.start/complete、request.cancel | 顺序/去重、断连恢复、精确取消匹配 |
| 服务端请求 | approval、clarify | 带 JSON-RPC id，同 id 回包，权限/过期校验；未知请求快速返回不支持 |
| 恢复结果字段 | inflight、open_requests | 从 resume/activate 或该版本支持的恢复结果读取，不等待虚构事件 |

连接在 gateway.ready 后声明 `client.capabilities {"server_requests": true}`；具体方法及结构纳入版本契约测试。消息展示源于元数据，不通过解析用户文本识别后台通知。

### 5.2 运行时边界和默认白名单

共享 Gateway 是服务入口目标，不等于共享所有运行状态。一个受控 Provider 配置也不等于必须共享 Profile 的可变数据。

首个探针使用专用隔离执行单元，不挂个人 Hermes home。默认只允许会话必需方法、消息/工具事件、审批/澄清回包与当前业务工具；禁止普通用户访问 `config.set`、任意 `command.dispatch`、MCP 热加载、shell/任意文件执行和未列入白名单的管理方法。未知能力默认关闭。

共享执行方案必须证明：Profile Memory 的自动注入与读写、会话搜索、Skill 可变状态、工作目录、浏览器 Cookie、事件订阅和子任务没有跨用户/项目路径。不能只禁用 memory 写工具却继续自动注入共享记忆。用户偏好只有在独立作用域和授权成立后才能持久化。

若共享状态隔离不成立，采用用户×项目隔离的执行单元（独立 profile/home、工作目录和浏览器上下文，必要时进程/容器）；这是安全要求，不自行宣称 Hermes 已提供全部隔离机制。实例拓扑在 Gate A0 以实测确定。无法实现则阻塞多用户发布；不得把两用户首版要求降成单用户签收。

### 5.3 可信身份到 MCP

- 用户/项目来自 Haitlify 登录态和成员关系。模型可提交资源参数，但不能提交有效授权主体。
- 选择固定 Hermes 版本的可信工具执行接入点，获取不能由模型改写的 session/turn/task 上下文，映射到服务端已认证执行绑定。
- 通过服务端间短期授权引用绑定 user/project/session/执行代次/tool scope/有效期。不得把身份放入模型 prompt，不得动态覆盖共享 MCP 连接 header 代表不同用户。
- 子任务/后台任务必须继承限定授权；无法验证继承的能力不开放。用户注销、停用、项目移除或授权撤销后，新工具调用重新鉴权失败。
- MCP 服务独立验证授权引用；缺失、过期、上下文不匹配时拒绝。插件或 middleware 异常不能绕过此检查；不依赖中间层默认是否 fail-open。
- Gate A0 必须实现并发 A/B 调用、伪造参数、失效授权、后台/子任务和接入点注入失败的拒绝探针。没有可靠接入点则阻塞，不猜测协议字段。

### 5.4 持久受理账本与幂等

Haitlify 为每次用户提交保存稳定 request ID、主体、会话、执行代次、输入 digest、受理状态和关联业务 operation ID。相同 ID+相同输入返回原受理记录；同 ID 不同输入拒绝。账本先持久化，再分发。

TUI 活跃会话重连不等于持久 prompt admission。发送后回执丢失时，不因缺少 inflight 就重发；先核对 Hermes 可核验记录及业务 operation。无法确定则 UNKNOWN，由用户明确决定后续动作。

业务副作用幂等键由服务端基于已授权 operation/revision/action 生成并持久化，跨浏览器重连、模型重试和进程重启复用；模型不能通过更换随机键绕过唯一性。合法再次执行必须创建新的明确授权 operation。

本地业务写入与账本在事务内关联；跨 Runner/外部系统使用受理记录、目标 operation ID 和查询对账，不承诺跨系统 exactly-once。账本保留覆盖可重试和审计周期，清理后拒绝旧请求重放，不把旧 ID 当新任务。

### 5.5 运行因果链与协议探针产物

每条执行必须关联 `Haitlify requestId → dispatchAttempt/执行代次 → Hermes session + 可核验 turn/run 标识 → business operationId → Runner runId → 结果/报告 revision`。这些是内部契约名，不假设 Hermes 有同名 wire 字段。受理先持久化，发送前记录 attempt，收到可信回执再绑定实际运行标识；无法绑定的发送记录保持 UNKNOWN，不用文本相似度猜测匹配。

A0 固定单一主协议、Hermes commit/digest、Bridge 契约版本，并保存脱敏原始帧与断言：会话创建、prompt 受理、消息/工具通知、同 ID 审批澄清回包、resume/open_requests、精确取消、未知请求拒绝、双主体并发、伪造/过期授权、后台/子任务身份传播。仅 ready/prompt 成功不足以通过。

对账查询来源是该固定版本的官方可验证会话/运行记录和业务 operation 回读，不读写 Hermes 数据库篡造运行。缺少可靠运行关联或持久受理时，记录 TUI 限制并评估官方 Runs API 是否满足全部交互合同；需要切换须更新 ADR 和测试矩阵，只选一个主协议，不自造 Hermes 内部运行协议。不能满足则 A0 阻塞。

## 6. 业务工具与脚本交接合同

### 6.1 工具按风险分层，不按发布阶段割裂

以下名称是拟议业务接口，不表示代码已存在。最小闭环只实现必需工具，不先铺全部目录。

- 只读：project.get、requirement.get、case.get、runner.run.get、evidence.get。
- 草稿：case.draft.save、review.save、report.draft.save。
- 探索与编译：exploration.request、evidence.register、input.bind、script.validate、script.compile、script.save。
- 副作用：run.authorize（仅真实 UI 可发起）、runner.run.request、runner.run.stop、report.confirm。

业务工具只完成确定性操作；Hermes 负责语义生成和修订。report.confirm 是平台内报告确认，不默认包含外部平台发布。不存在万能 SQL/REST/执行操作工具。

### 6.2 需求输入的有限支持矩阵（首版基线提案）

| 输入 | 预期处理 | 不完整时行为 |
|---|---|---|
| 粘贴文本、TXT/Markdown | 保存版本和段落锚点 | 编码/截断明确报错 |
| PNG/JPEG 图片 | 视觉理解并绑定原图、区域和模型证据 | 不支持视觉则 BLOCKED，不用尺寸摘要冒充理解 |
| 含文本/图片/表格的 PDF、DOCX | 页码或段落/表格/图片锚点与解析覆盖清单 | 缺失图表标 PARTIAL，缺少影响测试的内容则澄清/阻塞 |
| 其他格式、Figma 在线导入、音视频 | 首版不默认支持 | 明确不支持或要求用户转换，不能静默丢弃 |

矩阵是待用户确认的范围建议，不擅自增加全部格式；Gate A0 冻结材料及支持范围后才签收输入能力。首版验收必须有图文混合材料及部分不可解析材料，不能全用纯文本。

### 6.3 受控探索

Hermes 原始 browser_exec 的 Python/JS 能力不能被当成只读沙箱。托管任务不直接开放原始任意代码浏览器；通过版本化受控探索工具暴露观察、导航和限定交互，语义选择仍由 Hermes 完成。

服务端策略限制目标环境/域名、网络出口、允许操作、凭据引用、操作次数和时限。禁止绕过代理访问未知目标、下载任意执行代码或操作其他会话。页面内容视作不可信输入，不能提升工具权限。

探索动作也可能写业务。无法判定副作用的点击/提交默认要求限定动作确认，优先使用隔离测试资源和可回收的数据；不得用“是探索”放行。HTTP GET/POST 不能作为副作用分类的唯一依据。无法在执行边界强制策略时阻塞探索，不用 Prompt 代替权限。

受控探索的最小动作集合为 observe、navigate、click、fill、select、wait、capture；动作必须有目标证据引用、环境和策略版本，返回执行结果及脱敏证据。observe/capture 只读；navigate/click/fill/select 按目标业务策略分类（自动保存表单也可能写入）；未知及 submit/保存/删除类动作必须绑定明确授权。禁止透传任意 Python/JS，底层复用验证过的浏览器/Runner 原语，不实现语义规划器。不支持的动作显式 BLOCKED。

探索和 Runner 均经服务端检查 credentialRef 的项目/环境/有效期，再由隔离执行器短暂解引用、登录并验证成功证据。首版 A1 必须跑一次登录、普通 fill/select、动态等待、受控提交和新上下文重放。需要 MFA/人工登录时产生明确 WAITING_USER 与到期处理，不以复制探索 Cookie 绕过。探索证据记录页面状态/目标定位/时间/动作结果，编译映射到同版本 Runner 原语；无映射则拒绝编译。

### 6.4 输入从来源到执行值

输入绑定区分 literal、authorizedDataRef、secretRef；由服务端保存来源、类型、作用域、版本和必要约束，不能由模型猜业务值。

普通数据由授权资源解析；秘密仅在受控执行边界短暂解引用，注入受限字段，不进入 prompt、对话、脚本正文、日志、截图或报告。秘密 digest 使用引用版本或受保护的 HMAC，不存可离线猜测的明文密码 hash。截图/DOM 证据在入库和上传前遮蔽敏感字段。

确认绑定输入引用版本和目标环境；执行前重新检查引用未撤销/变更。缺值返回结构化缺项供集中澄清；改值、换环境或换脚本需重确认。验收必须实际完成 fill/select，并覆盖缺值、改值、过期引用、秘密泄漏拒绝。

### 6.5 探索到 Runner 的版本化交接包

必须保存：schemaVersion、用户/项目关联、需求/用例 revision、环境、身份/凭据引用、初始化/清理步骤、输入来源绑定、页面证据及时间/指纹、Locator 和断言来源、actions、脚本 revision/hash、确认和授权引用。

责任链：Hermes 产生候选动作 → Haitlify 验证来源/权限/结构/证据有效性 → 确定性编译为 Runner 支持格式 → 保存不可变脚本 → UI 确认 → Runner 校验交接包并执行同一 hash。

Runner 新建隔离浏览器上下文，通过授权凭据引用重建登录和前置状态，不默认复制探索 Cookie/可变文件。证据过期、页面指纹不符或前置状态无法建立时明确失败，要求重新探索/确认，不能静默修复后继续已批准版本。

编译失败返回错误位置和原因，由 Hermes 在原任务中修订；Haitlify 不自行循环调用模型。脚本至少有业务相关可执行断言，不用截图存在或页面加载代替业务断言。

### 6.6 报告和执行成功判定

报告关联全部要求执行的用例/分支、脚本版本、输入引用、真实 run/step/evidence、断言结果、未执行/阻塞项、环境和清理结果。统计由确定性业务逻辑计算，Hermes 只提供有引用的分析，不改写原始事实。

报告生成成功、测试通过、业务正式接受是三个独立状态。资源未清理或证据缺失不能显示完整闭环成功；有效发现目标系统缺陷可以是正确测试结果，不能用重跑挑选成功的一次覆盖原记录。

### 6.7 清理与报告封口

每个分配的浏览器/账号租约/测试记录登记资源级账本：operation、所有者、清理执行器、期限、最大尝试次数、补偿操作、回读证据。执行器 finally 做首次回收，Haitlify 确定性清理 worker 接管进程异常后的超时回收；不是让模型反复猜清理命令。

资源状态为 ALLOCATED→CLEANING→CLEANED；失败进入 CLEANUP_FAILED，到期/超限转 MANUAL_REQUIRED 并指定有权限的处理人。再次清理必须幂等；凭据撤销或资源归属不明时停止自动操作。人工处置附回读可转 CLEANED；确实不可恢复可记录 UNRECOVERABLE 和风险责任人，但不能显示完整闭环成功。限次/时限在 A1 任务卡批准后固定，不无限后台重试。

报告状态为 GENERATED→FACT_COMPLETE→ACCEPTED/REJECTED；修订建立新 revision，旧版本标 SUPERSEDED 并保留。FACT_COMPLETE 要求步骤、外部副作用及清理全部可核查；残留 UNKNOWN/CLEANUP_FAILED 只能交付标有未结事项的暂存报告。`report.confirm` 只接受项目授权审核者真实 UI 操作（模型无自批权限），绑定报告 hash/revision。发现目标系统 bug 的事实完整报告可以被接受，但测试结果仍为 failed。

任务仅在执行结果可核查、资源均已清理、正式报告被接受后为 CLOSED；报告拒绝为待修订，不自动重新执行。无法清理但人工结束处理时使用 CLOSED_WITH_UNRESOLVED，保留追踪事项，不算验收通过。正常流程第 8 步之后必须进入该报告确认和任务关闭步骤。

## 7. 首次启动安全与旧 AI 拆除

### 7.1 首次启动之前的硬关卡 A0-E

旧 Compose 曾固定旧容器名并建议复用旧项目卷；该文件现已从新仓删除，现行部署指引已撤下。新隔离 Compose 与启动预检尚未实现，不能以本次清理替代 A0-E 通过。

先交付新仓专用 Compose 和启动说明：独立 project/container/port/network/volume/database/Hermes home/产物路径，不挂个人运行目录，不连接旧数据库；移除新启动入口中复用旧资源的指导。

解析 Compose 配置并比对实际目标，验证不指向旧资源且端口无冲突后，才允许启动任何服务或迁移。为同机旧环境保留启动前后资源清单。禁止 down -v 或覆盖旧数据库。当前已有 Flyway 文件不改写；若新建 schema 基线，独立迁移位置仅对新库生效。

启动保护必须落成代码，不仅是说明：新仓唯一受支持启动入口先解析配置并生成绑定配置 hash 的预检结果；服务启动/迁移入口复验目标环境和资源命名，缺失、不匹配时拒绝启动。CI 检查禁止旧 project/container/volume、旧库、个人 Hermes home 和凭据路径；开发进程使用最小权限，不能靠全局 Docker/数据库权限访问旧资源。管理员手动改代码仍可能绕过，不能宣称主机 root 不可绕过。

A0-E 前只允许静态检查。通过后允许隔离合成数据探针；真实模型使用已批准测试 Provider 和费用上限；真实业务只读数据须有授权，真实业务写入仅在 A1 任务卡授权后开放。移除新仓旧启动入口，不改旧归档仓库。准备环境时停用旧服务不等于新环境预检已通过。

### 7.2 拆除与新闭环并行推进，但不留双运行时

按依赖清单分批删除旧 Loop、模型 adapter、阶段 prompt、任务路由和旧 UI。根目录/资源目录 AGENT.md、Skill/规则、后台启动项、测试夹具、环境变量、部署与旧说明都列入清单，不只删除类。

先隔离新入口并禁止旧 AI 路径被调用；按首条闭环需要抽离或重建确定性职责，再删除相应旧代码。无需先清理完整仓库才开始闭环，也不等首版结束才开始拆除。

每批有删除/复用/重建理由、调用方检查、编译/回归与独立复核。旧实现专属测试可退役但需记录；权限、输入、证据、验收和资源回收等行为测试必须迁移，不能用删除测试换通过。

## 8. 官方升级与跨系统恢复

- 锁定 Hermes release/commit/digest、Bridge 契约和业务工具 schema；不默认直接跟随 main。
- 第一条闭环即纳入协议兼容测试；自动版本发现和候选环境验证属于首版，不推成后续优化。
- UI 只展示支持的能力；未知交互请求拒绝、未知非交互事件安全展示或告警。新增工具/权限升级后不自动启用。
- 升级先停新任务、drain 活跃工作，必要时显式取消并完成对账。记录停写范围。
- 固定版本的备份清单覆盖 Hermes state.db 及使用功能依赖的配置、Skill/插件版本、工作目录/附件索引与状态；凭据只通过受保护备份/引用恢复，不打包进仓库。记录对应 Haitlify 绑定/游标的检查点。
- **没有新写入**：验证备份和旧版本相容后恢复；**已经有新写入**：保留并隔离候选状态，不自动覆盖回旧快照。对新 Session、业务操作、Runner 结果、待审批和游标逐项对账；失去运行时历史的绑定标孤立/UNKNOWN，旧待审批失效并重新确认，已执行业务不重发。
- Haitlify 幂等和审计记录不随 Hermes 快照倒退；不能丢掉升级后副作用的记录。明确恢复点、可能丢失的会话记录及用户批准，不能声称无损回滚。
- 候选兼容、真实闭环、故障恢复通过独立复核后，才人工批准生产切换。首版验证使用两个固定可获得版本；若无可验证候选版本则升级 Gate BLOCKED，不拿同版本重启冒充跨版本升级。没有生产窗口时可以签收测试环境升级演练，不能宣称生产已经升级。

### 8.1 发布包与切换记录

每次候选升级生成不可变发布记录：新旧 Hermes digest/Bridge/tool schema、配置与插件/Skill版本、状态/附件兼容清单、备份位置引用和校验值、停写点、drain 结果、候选测试、批准人、恢复点和可接受损失范围。凭据不进入发布记录。

切换顺序：阻止新受理→活动任务完成或已对账停止→备份并验证可恢复→切换受控路由到候选→受限 smoke→解除停写。任一步失败保持停写，对账后按第8节恢复，不自动让新旧 owner 同时运行同一会话。首次业务新写入记录为回滚决策分界。

恢复后逐项处理：原运行已完成则仅展示回读结果；未派发请求可在重新验证授权后派发；已派发不明请求保持 UNKNOWN；丢失会话新建受限会话并关联已知业务对象；待审批全部失效重确认。重跑建立新 operation，且必须先处置旧副作用。审批人确认恢复记录后才恢复接收业务，不能用容器健康证明恢复。

## 9. 实施顺序：先安全，再完整窄链路，再扩覆盖

### 9.1 阶段 A0：受限预研与安全启动

交付 A0-E 独立环境、删除依赖清单、选定 Hermes 版本能力矩阵、协议分型、可信身份探针、账本设计、首条任务与验收基线。

实际探针只覆盖必要会话/审批/澄清/恢复及一个真实只读业务工具，包含两主体并发和拒绝路径；不先建完整工具目录、管理中心或 UI 体系。

退出 Gate：目标环境确认无旧资源引用；关键协议和身份传递有证据；允许的执行单元隔离方案明确；业务样本/范围/基线经用户确认。仅文档或 ping 不算通过。A0 未通过不开展真实写入执行，但允许完善受限原型及方案。

### 9.1.1 A0 时间盒、A1 任务卡与启动触发

A0 开始前记录用户批准的时间/调用费用上限；尚无批准值时不发起付费探针。到限即暂停、给出证据/阻塞/替代方案，不以继续完善文档绕过预算。A0 安全和协议退出条件满足后，在已获实施授权范围内直接推进已冻结 A1，不再追加管理中心或其他预研；没有新增授权则明确等待，不无限设计。

A0 必交版本化 A1 任务卡，字段：真实需求文件 hash/版本、授权目标项目和测试环境、受保护凭据引用、可回收数据、登录与前置条件、普通输入与 secretRef、fill/select/动态页/受控提交动作、业务断言、目标写入回读、清理责任与期限/次数、故障注入、禁止人工绕过项、用户批准记录和证据路径。禁止把账号/密码/目标内部数据原值放入共享计划。

卡片当前状态为 **待选定真实任务和授权**，不能虚构现成样本。至少选包含登录、输入、实际可回收写入/回读的任务；无此条件的静态只读演示不满足 A1。任务卡及 hash 是 A1 Gate 的直接依据，测试夹具负责故障注入但不能替代授权业务环境。

### 9.2 阶段 A1：一条真实完整窄链路（最早业务验证）

实现仅此任务必需的 UI/工具，从需求、草稿、用户确认、受控探索、输入绑定、确定性编译、脚本保存、执行确认、Runner 实跑到报告和资源回收。普通输入、至少一个业务断言、引用证据必须实际经过完整链路；不能人工绕过中间层代写脚本冒充自动生成。

同时实现本链路所需的身份隔离、请求账本、重复提交拒绝、取消/UNKNOWN 和资源释放；安全与副作用可靠性不是留到加固阶段才做。

A1 Gate：独立复核重放同一任务，实际写入回读，Runner 新上下文可重放，旧 AI 无调用，报告事实一致且资源清理。A1 失败只修复本链路，不横向扩工具、铺全套页面或做无关重构。A1 通过只是内部里程碑。

### 9.3 阶段 A2：完整首版范围与四类痛点验收

在 A1 通路上扩充批准的输入格式、业务分支、图文/表格、动态页、表单、异常与保留任务；落实全局 UI、资产修改/重新确认、任务生命周期展示和所有首版工具。

Gate：需求覆盖、人工修订量、重复运行、操作成本均按冻结基线统计；已确认范围无遗漏。不得单独完成一个只读模块就结束交付。

### 9.4 阶段 A3：故障、并发、升级与恢复演练

扩充真实故障矩阵：受理回执丢失、业务写入后断链、Gateway/Runner 重启、取消期间完成操作、跨用户访问、成员撤销、凭据过期、并发审批、多客户端恢复、资源回收失败。A1 已具备必要保护，本阶段证明覆盖而非首次加入保护。

完成版本发现、候选契约测试、跨版本闭环、升级后新写入对账、备份恢复与人工发布控制。

Gate：无重复副作用、无跨域泄漏、UNKNOWN 不伪造成功、升级/恢复符合第 8 节；无法满足则阻断首版。

### 9.5 阶段 A4：完整签收与交付

首版合同全部项均有最新独立复核和证据；旧 AI 在入口/后台/配置/部署零运行依赖；冷启动、停止、运维恢复和已批准格式支持可复现。删除遗留代码完成不等于交付。

交付任务清单、版本锁定、运行手册、验收材料与证据索引、已知限制。只有用户明确改变范围才能取消合同项，不能改名为“以后扩展”。

### 9.6 推进和止损

每个任务关联合同 ID、入口、工具/服务、测试、证据、负责人和复核。状态区分未开始/实现中/待实测/待复核/通过/失败/外部阻塞/用户批准取消。阶段报告不按代码量或测试条数计算交付百分比。

连续两轮同一关键闭环失败，停止扩张，给根因、修订方案和投入报告；不是自动换仓或缩范围。A0 时间/费用预算在开始付费调用前由用户确认。无真实凭据、站点授权、预算或样本时列为具体外部阻塞，做不依赖它的工作，但不能以 mock 签收业务 Gate。
