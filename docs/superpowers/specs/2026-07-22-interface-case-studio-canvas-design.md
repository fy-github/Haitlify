# 接口用例页 Studio Canvas 适配设计规范

## 状态

视觉设计已于 2026-07-22 通过浏览器伴侣确认，等待用户审阅本规范后进入实现计划。

## 目标

将现有“接口用例”工作区迁移到已批准的 Studio Canvas 浅色视觉语言，形成与 Web 用例页一致的应用外壳、阶段导航、操作反馈和响应式行为，同时保留接口用例现有业务能力：

- OpenAPI JSON 导入
- 接口资源筛选与多选
- 用例模板与生成颗粒度选择
- 接口用例生成
- AI 评审、补充缺失用例和评审结果回写
- 保存到用例库
- 转 API 自动化
- CSV 导出
- 现有接口资源列表、编辑、上下移动、删除和相关数据操作

本次是 UI/交互迁移，不改变 OpenAPI 解析、用例生成、AI 评审、持久化、自动化转换或导出接口契约。

## 核心交互模型

接口页使用已有 `WorkflowHeader` 组件的布局和状态样式，替换为接口专用的四个阶段数据：

`导入接口 -> 配置生成 -> AI 评审 -> 保存 / 交付`

这里的“保持一致”包含以下内容：

- 与 Web 阶段图相同的高度、布局比例、顶部状态线、完成/当前/禁用状态和横向溢出行为。
- 阶段按钮使用相同的键盘、`aria-current`、禁用和焦点规则。
- 阶段图不新增接口专用卡片式设计，不使用另一套颜色或连接线。
- 阶段数据可以使用四步，但组件结构和状态类名必须继续由 `WorkflowHeader` 提供。

每个阶段只有一个深蓝色主操作，阶段以外的次级动作不抢占主操作层级。

### 阶段 1：导入接口

- 左侧上下文区列出已导入 OpenAPI 来源，显示文件名、接口数量、解析状态和替换/重试/移除操作。
- 中央区展示导入入口、解析中的进度、解析后的接口摘要和来源错误。
- 主操作为“解析接口”或“继续到配置生成”，根据当前解析状态切换。
- `pickOpenApiFiles`、`importOpenApiFiles` 和 `importOpenApiPayloads` 的行为不变。
- 支持空状态、解析中、局部成功、解析失败和重新挂载/替换来源。

### 阶段 2：配置生成

- 左侧上下文区承载当前 OpenAPI 来源、接口路径/摘要关键词、请求方法、用例模板和基础/风险/完整颗粒度。
- 中央区承载接口资源选择和生成结果；筛选只改变展示范围，不丢失已选择接口。
- 生成前中央区可以展示已筛选接口；生成后用例表格成为最大工作区域。
- 主操作为“生成用例”。没有来源或没有选中接口时保持禁用或给出明确提示。
- `generateCases` 继续使用当前模板字段、启用的接口用例类型和颗粒度逻辑；不在 UI 层重新实现生成规则。

### 阶段 3：AI 评审

- 中央区继续显示生成用例表格，支持行选择和逐条操作。
- 右侧显示上下文 AI 评审检查器，展示评分、严重级别、发现、证据和决策状态；未处于评审阶段时收起为抽屉入口。
- 主操作在未评审时为“运行 AI 评审”；已有结果时为“继续交付”。
- 支持“应用建议”“忽略”“一键补充缺失用例”、逐条决策和批量决策。
- `runAiReview`、`supplementMissingCases` 和现有 `reviewFindings` 数据结构保持行为一致；评审失败不能清空已生成用例。

### 阶段 4：保存 / 交付

- 中央区显示待交付用例数量、评审完成情况和交付摘要。
- 主操作为“保存用例”，保存与转自动化/执行分离。
- 次级操作为“转 API 自动化”和“导出 CSV”；转自动化前保留现有准备与环境检查，导出不依赖执行成功。
- `saveCases`、`transferGeneratedCasesToAutomation` 和 `exportCsv` 的持久化、消息和导航行为保持不变。
- 为保持现有接口页行为，生成结果存在时交付阶段即可访问；若尚未尝试 AI 评审，页面显示提示但不阻断保存、转自动化或导出。推荐路径仍然是先完成评审再交付。
- 保存完成后允许离开当前任务，不能因为自动化执行失败而撤销已保存用例。

## 页面结构

### 共享外壳

- 继续使用当前 `AppShell`、`PrimarySidebar` 和 `GlobalTopbar`。
- 侧边栏保持 `168px` 展开、`56px` 收起；展开时显示图标和中文标题。
- 顶部侧栏开关继续是全局顶栏第一个命令。
- 接口用例页使用 `workspace` 的 Studio Canvas 页面底色，不重新引入旧 `topbar` 的独立外壳。

### 接口任务头

使用 `WorkflowHeader`，包含：

- 项目/接口任务标题
- 自动保存状态与时间
- 四阶段导航
- 次级新建草稿或模式动作
- 当前阶段唯一主操作

接口页不可保留旧的 `topbar`、`control-strip`、`main-grid` 作为视觉外壳。若保留旧 class，只能作为过渡兼容选择器，不能承担新页面布局。

### 三栏工作画布

桌面宽度（约 `>= 1280px`）采用三栏：

1. 左侧“接口与生成配置”上下文区：OpenAPI 来源、接口筛选、方法、模板、颗粒度。
2. 中央“生成用例”主画布：接口/用例表格、操作栏、批量操作和状态。
3. 右侧“AI 质量评审”检查器：仅在评审阶段默认展开，其他阶段收起或显示入口。

上下文区与检查器不能使用多层嵌套卡片；使用一个平面工作面、低噪声边框和轻微表面差异表达区域层级。

## 生成用例操作区

生成用例必须同时提供“顶部工具栏”和“表格操作列”：

### 顶部工具栏

- 搜索用例标题/接口路径
- 方法筛选
- 评审状态筛选
- 已选数量
- 批量接受或应用建议
- 更多批量操作入口

工具栏控件使用稳定高度，内容变化不能推动表格上下跳动。搜索和筛选必须保留当前接口/用例选择状态；空结果显示清除筛选操作。

### 表格操作列

固定在右侧，保留当前接口用例行为：

- 查看/选中详情
- 编辑
- 上移
- 下移
- 删除

图标按钮使用 Lucide 图标，必须有 `aria-label`、`title` 或 Tooltip；删除使用语义危险色，但不能只依靠颜色表达危险状态。接口页现有操作栏逻辑（移动、编辑、删除）不能因重排而删除。

## 状态与恢复

所有状态都保留用户已生成的数据：

- 首次空状态：说明需要导入 OpenAPI，并提供导入按钮。
- 解析中/生成中/评审中：显示进度和阶段状态，保留可访问的取消/返回路径。
- 局部成功：标记部分完成，允许继续查看成功结果和只重试失败项。
- 筛选为空：显示清除筛选，不把它误报为没有用例。
- 来源错误：错误绑定到来源项，提供重试、替换或移除。
- AI 评审失败：保留生成结果，提供重试并允许用户回到生成阶段。
- 保存/同步冲突：沿用当前工作区同步提示，可选择推送本地或使用后端。
- 离线：草稿仍可留在本机；联网后继续同步。

错误、警告和成功状态必须同时使用文字/图标与颜色，不能只用色块。

## 视觉规则

- 浅色主题默认使用当前 token：主操作/AI 为深蓝 `#2854A6`，而不是组件内硬编码颜色。
- `--brand-primary`、hover、active、soft、border 和 focus token 继续作为唯一品牌色入口；深色和 system 模式接口继续保留。
- 页面约 80% 为中性表面，品牌色只用于主操作、当前阶段、AI 焦点和少量强调。
- 正文沿用 system-first 中文字体栈；避免锋利的大号字、负字距和过重字重。
- 常规控件/面板使用 `6px` 到 `8px` 圆角；优先使用边框和表面差异，阴影只用于抽屉、弹层等抬升表面。
- 阶段图、工具栏、表格、按钮和抽屉使用固定尺寸，避免加载或长文本导致布局跳动。
- 所有图标命令使用 Lucide；图标按钮配 Tooltip 与可见焦点。

## 响应式行为

- `>= 1280px`：展开或收起全局侧边栏；三栏画布可同时显示。
- `1024px` 左右：侧边栏默认收起；左上下文区和右检查器变为抽屉按钮，中央表格保持操作栏与固定操作列。
- 更窄屏幕：阶段导航横向滚动；操作栏允许横向滚动或分组折叠；表格不强行缩小文字。
- 抽屉使用现有 `ResponsiveDrawer` 语义与焦点管理，不新增悬浮开关位置。
- 移动尺寸只保证功能可达，不承诺完整桌面表格编辑密度。

## 实现边界

### 建议新增或复用的 UI 单元

- 复用 `WorkflowHeader` 作为接口阶段导航。
- 新增 `InterfaceCaseContextPane`：来源、接口列表和生成配置。
- 新增 `InterfaceCaseTable` 或将现有接口 `el-table` 提取为局部组件：包含工具栏、选择、操作列和空/加载状态。
- 新增 `InterfaceReviewInspector`：将现有 `reviewFindings` 映射成上下文检查器；不改变评审领域模型。
- 复用 `ResponsiveDrawer` 处理窄屏上下文区和 AI 检查器。
- 新增接口阶段 view-model 只负责状态映射和主操作文案，不复制生成/保存业务规则。

### 不在本次范围

- 不重写 OpenAPI parser、case generator、AI review domain 或 persistence repository。
- 不同时改造用例库、报告、缺陷和其他模块。
- 不实现完整深色视觉，只保留 light/dark/system token 接口。
- 不删除旧接口业务函数，迁移期间允许保留兼容逻辑，但旧布局不得继续作为接口页入口。

## 验收标准

### 行为

- 可以完成“导入接口 -> 配置生成 -> AI 评审 -> 保存/交付”，无需回到旧接口工作区。
- OpenAPI 导入、筛选、多选、模板、颗粒度和生成结果与迁移前一致。
- AI 评审、补充缺失用例、忽略/应用建议和评审状态与迁移前一致。
- 保存、转 API 自动化、执行前检查和 CSV 导出继续可用，并保持保存独立于执行。
- 表格工具栏和操作列在有数据、筛选为空、部分成功和错误状态下都可达。

### 视觉

- 顶部阶段图使用 Web 的 `WorkflowHeader` 视觉和交互，不出现接口专用阶段卡片。
- 三栏结构、深蓝主操作、浅色表面、柔和字体和 PNG 基准一致。
- 侧栏在 `168px / 56px` 两种状态下无溢出；开关位置与 Web 保持一致。
- 1024px 左右能够通过抽屉访问接口上下文和 AI 评审，表格操作栏与操作列不消失。
- 检查 `1440x900`、`1280x800`、`1024x768` 截图，确认无空白渲染、文本溢出、操作重叠和布局跳动。

### 测试

- 补充接口页面结构测试：`WorkflowHeader`、阶段状态、操作栏、操作列和响应式 drawer 入口。
- 保留并运行现有接口生成、评审、保存、自动化转换、导出相关 Vitest 测试。
- 独立运行 `npm run build`，不以 Vitest 代替 TypeScript/生产构建检查。
- 使用 Playwright 覆盖四阶段主流程、筛选/批量操作、AI 评审、保存与转自动化，以及桌面/窄屏截图。
- 运行 axe 或等价无障碍检查，重点验证阶段按钮、图标操作、抽屉焦点和表格操作列。

## 迁移原则

实现过程中每个阶段都以本规范和 `docs/superpowers/design-assets/interface-case/` 为视觉源，不恢复旧接口 UI，不复制 Web 业务规则到接口领域，也不为了视觉重排删除已有操作。任何需要偏离设计稿的地方必须先更新规范和设计资产，再修改实现。
