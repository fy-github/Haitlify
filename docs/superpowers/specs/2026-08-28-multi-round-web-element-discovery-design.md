# 多轮 Web 页面元素探索设计

## 文档状态

- 状态：已确认
- 日期：2026-08-28
- 适用范围：Web 用例自动化编译阶段的页面定位、元素取证、失败重试和素材沉淀
- 探索预算：单测试点最多 5 轮，最长 90 秒

## 背景

当前 Web 自动化编译先根据自然语言计划打开一个候选页面，再采集一次可见元素。该机制在目标入口隐藏于多级菜单、页面存在遮罩、目标元素不在首屏、业务状态不匹配或自然语言计划缺少准确路由时，容易反复把首页或全局导航元素交给 AI，最终产生与测试目标不一致的断言。

本设计将单轮取证升级为有预算、有评分、有安全边界的多轮页面探索。探索器负责找到正确页面和目标元素，AI 编译器只在证据达到阈值后生成 DSL，避免使用同一份错误证据反复修复模型输出。

## 目标

- 针对不同需求和页面结构自动进行多轮页面查找。
- 最大化命中目标页面、目标业务状态和目标元素的概率。
- 能够识别并修正登录页、首页、错误模块页、遮罩层和元素不在视口等情况。
- 严格限制探索动作，禁止误触提交、删除、停用、保存等业务操作。
- 将成功路由、导航轨迹和定位器沉淀为可复用且可复核的页面知识。
- 单点探索失败不得阻断其他测试点。

## 非目标

- 不执行测试用例中的真实业务操作。
- 不通过强制点击绕过不可见、禁用或被遮挡元素。
- 不遍历站外链接，不突破现有网络和登录安全策略。
- 不保证在目标数据不存在、账号无权限或页面本身不可用时一定生成自动化用例。

## 方案选择

采用“确定性探索状态机 + AI 语义辅助”的混合方案。

- 确定性状态机控制浏览器动作、预算、退出条件和安全边界。
- AI 只负责把自然语言用例解析为目标意图、补充页面或元素同义词，并对候选证据进行语义排序。
- 最终是否允许进入编译由确定性评分和浏览器实证共同决定，不能由 AI 自行放宽。

不采用完全由 AI 控制浏览器的方案，因为其动作不可预测、成本较高且难以证明不会误操作；不采用纯规则遍历方案，因为跨项目页面命名和结构差异会显著降低命中率。

## 核心数据结构

### TargetIntent

每个测试点在探索前形成目标意图：

- `pageAliases`：页面名称及同义词。
- `routeHints`：自然语言计划、历史知识或环境配置中的路由提示。
- `elementTerms`：必须找到的目标元素词，例如“停用”“重新开通”。
- `actionTerms`：操作意图，例如“查看”“切换”“筛选”。
- `stateTerms`：业务状态，例如“即将到期”“已停用”。
- `expectedTexts`：自然语言预期中可观察的文案。
- `negativeTerms`：不得替代业务断言的全局导航词。

### ExplorationBudget

- `maxRounds = 5`
- `maxDurationMs = 90000`
- `maxSameFailureRetries = 2`
- `maxLoginRetries = 1`
- `maxReloads = 1`
- `maxPaginationSteps = 3`

### PageObservation

每轮保存：

- 当前 URL、标题、面包屑、激活菜单和 DOM 指纹。
- 可见菜单、链接、Tab、表格列、业务状态和交互元素。
- iframe、Shadow DOM、滚动容器和虚拟列表信息。
- dialog、遮罩、加载层、Cookie 提示和引导层信息。
- 候选元素的可见性、可用性、遮挡情况、唯一性和上下文。

### ExplorationResult

- `status`：`matched`、`blocked` 或 `exhausted`。
- 最终页面 URL、导航轨迹和轮次数。
- 页面分数、元素分数、状态分数及命中依据。
- 可用于生成的元素证据和定位器。
- 未命中原因、已尝试策略和下一次人工建议。

## 探索状态机

每个测试点独立执行以下状态：

1. `INTENT`：解析目标页面、元素、状态和预期文案。
2. `REUSE`：查询已验证的页面路由、导航轨迹和定位器素材。
3. `OPEN`：打开最高置信度候选 URL；没有可靠路由时从 Web 环境 Base URL 开始。
4. `OBSERVE`：采集页面、遮罩、容器和元素证据。
5. `SCORE`：计算页面、元素和状态匹配分数。
6. `CORRECT`：未达阈值时选择一个安全修正动作。
7. `REOBSERVE`：动作完成后重新采集，不复用动作前 DOM。
8. `MATCHED`：证据达到阈值，交给 AI 编译器。
9. `BLOCKED`：遇到登录、权限、网络或页面不可用问题。
10. `EXHAUSTED`：预算耗尽或连续两轮页面和候选证据均无变化。

探索状态必须记录轮次、耗时、动作、页面 URL、分数变化和退出原因。

## 证据评分

总分 100 分：

- 页面匹配最高 40 分：URL、标题、面包屑、激活菜单和页面主标题。
- 元素匹配最高 40 分：元素文本、可访问名称、角色、所在表格列或数据行上下文。
- 状态匹配最高 20 分：目标业务状态、前置条件和预期文案。

进入 AI 编译必须同时满足：

- 总分不低于 70。
- 元素匹配不低于 25。
- 至少存在一个浏览器实际采集的业务元素定位器。
- 业务断言不能只命中 `negativeTerms` 中的全局导航元素。
- Locator 必须唯一或已通过行、列、区域上下文限定为唯一目标。

## 安全动作白名单

探索器只能执行：

- 搜索菜单并选择同站菜单结果。
- 点击菜单项、导航链接、面包屑和只读 Tab。
- 展开导航、折叠区、树节点或详情区域。
- 在页面和指定滚动容器内滚动。
- 将目标候选滚动到视口内。
- 浏览最多 3 个分页页码。
- 关闭安全遮罩、取消弹窗、按 Escape。
- 返回上一稳定页面。
- 在 Locator 失效时刷新一次。
- 登录态失效时按现有环境配置重新登录一次。

以下动作永久禁止用于探索：

- 点击确定、提交、保存、删除、停用、启用、开通、支付、发送、上传等业务按钮。
- 输入业务表单字段或提交搜索菜单以外的表单。
- 访问站外 URL。
- 使用 `force` 绕过不可见、遮挡或禁用状态。
- 执行自然语言用例中的业务步骤。

## 重试策略

重试必须改变探索策略，禁止原样重放：

| 失败类型 | 下一轮策略 | 终止条件 |
| --- | --- | --- |
| 目标页面不匹配 | 页面别名搜索菜单、展开导航、尝试历史路由、返回稳定页 | 所有候选路径耗尽 |
| 仍停留登录页 | 重新登录一次并检查成功判定 | 第二次仍在登录页 |
| 页面无目标元素 | 滚动、展开区域、切换相关 Tab、检查分页和 iframe | 连续两轮 DOM 指纹与候选不变 |
| 元素被遮挡 | 识别遮罩，执行关闭、取消、稍后或 Escape | 只能通过确认类按钮关闭 |
| Locator 不唯一 | 通过目标状态行、列名、父区域或相邻文本缩小作用域 | 仍无法得到唯一 Locator |
| Locator 失效 | 刷新一次并重新采集，将旧素材标记待复核 | 刷新后仍失效 |
| AI 断言不匹配 | 提取缺失目标词，返回探索器重新取证 | 新证据仍不达阈值 |
| 网络或页面错误 | 在预算内等待一次并重新打开稳定 URL | 同类错误累计两次 |

同一种失败最多重试两次。连续两轮 URL、DOM 指纹、目标候选和分数均无变化时提前结束。

## 遮挡和不可见元素修正

- 检测 `dialog`、`aria-modal`、高层级遮罩、全屏加载层和固定定位引导层。
- 关闭动作只允许“关闭、取消、稍后、知道了”和 Escape。
- 目标元素存在但不可见时，先判断是遮挡、折叠、视口外、容器滚动还是虚拟列表未渲染。
- 对视口外元素执行滚动，不使用强制点击。
- 对滚动容器分别采集首屏、目标附近和底部证据。
- 对 iframe 和可访问 Shadow DOM 分别建立作用域，Locator 必须保留作用域信息。

## 错页识别和修正

满足任一条件即认为可能错页：

- 页面分数低于 20。
- 当前 URL 为登录、首页或项目页，目标页面名称未在标题、面包屑、激活菜单或主内容出现。
- 采集元素仅包含全局导航词。
- 页面 URL 与历史成功路由明显冲突。

修正顺序：

1. 使用 `pageAliases` 搜索菜单。
2. 点击完全匹配或最长语义匹配的安全菜单结果。
3. 展开与页面别名相关的一级导航和二级菜单。
4. 尝试已验证的历史路由。
5. 返回上一稳定页面并尝试下一候选路径。

每次跳转后必须重新校验 URL、标题、面包屑和目标元素，不得仅凭点击成功判定已到目标页。

## 提高定位成功率

- 优先级：`data-testid` > 唯一 role + accessible name > 稳定 id > 文本 > 结构化 CSS。
- 对表格操作按钮必须绑定目标状态行或业务主键行，禁止选择页面上第一个同名按钮。
- 对 Tab、列、状态和提示文案同时保留元素文本与上下文文本。
- 组合 DOM、可访问树和截图 OCR 候选，但最终 Locator 必须由浏览器 DOM 证据验证。
- 成功执行后增加 Locator 置信度；连续失败两次则自动退役并重新采集。
- 页面结构指纹变化时降低旧素材优先级，不直接复用。

## 页面知识沉淀

成功探索后保存：

- 页面别名到稳定路由的映射。
- 从 Base URL 到目标页面的安全导航轨迹。
- 页面指纹、目标元素 Locator、角色、名称和上下文。
- 命中的测试目标词、业务状态和环境 ID。
- 最近验证时间、成功次数、失败次数和置信度。

下次探索先复用高置信度知识，但必须执行轻量实时复核。路由或 Locator 复核失败时立即降级到多轮探索。

## 服务边界

### Platform

- 从自然语言计划构建 `TargetIntent` 和 `ExplorationBudget`。
- 调用 Web Runner 执行一轮或多轮探索。
- 保存探索事件、结果和页面知识。
- 只把达标证据交给 AI 编译器。
- 单点失败时标记阻塞并继续其他测试点。

### Web Runner

- 维护单个测试点的浏览器会话和探索状态机。
- 负责观察、评分所需的原始证据和安全动作执行。
- 返回每轮页面观察、动作、导航轨迹和最终 Locator 证据。
- 不接收或执行业务操作动作。

### AI 编译器

- 使用已通过评分的证据生成 DSL。
- 生成失败时返回结构化缺口，例如缺少目标元素、状态上下文或唯一定位器。
- 不允许自行扩大浏览器动作白名单。

## 可观测性

Agent 工作区按测试点展示：

- 当前探索轮次和总预算。
- 当前页面 URL 和页面匹配分数。
- 已执行的安全修正动作。
- 元素候选数、最高元素分数和命中依据。
- 遮挡、错页、登录、权限和 Locator 歧义原因。
- 最终使用的导航轨迹和证据来源。

事件摘要继续受数据库长度限制，完整诊断以结构化 JSON 保存，UI 展示精简摘要。

## 接口演进

现有 `navigationHints` 扩展为探索请求：

- `targetIntent`
- `budget`
- `allowedActions`
- `previousAttempts`

探索响应新增：

- `status`
- `rounds`
- `finalObservation`
- `scores`
- `navigationTrail`
- `elements`
- `failureReason`

旧请求缺少新字段时保持当前单轮行为，确保兼容已有调用方。

## 测试策略

### Web Runner

- 目标菜单直接可见。
- 目标菜单隐藏，需要菜单搜索。
- 目标位于两级导航、折叠区、Tab、分页、iframe 和滚动容器。
- 目标被可安全关闭的遮罩挡住。
- 遮罩只能通过确认业务动作关闭时必须阻塞。
- 错误首页、登录重定向、权限不足和站外链接。
- 连续两轮无变化时提前退出。
- 探索预算和动作白名单不可绕过。

### Platform

- 目标意图构建和评分阈值。
- 证据不达标时不得调用 AI 编译。
- AI 返回语义断言缺口后触发重新探索。
- 单点耗尽预算后继续其他测试点。
- 页面知识成功沉淀、实时复核和失败退役。
- 长事件和结构化诊断不会导致数据库写入失败。

### 端到端验收

- 从项目首页自动搜索并进入威胁情报页面，定位目标状态行内的停用按钮。
- 对不同模块页面无需新增硬编码路由即可完成探索。
- 遮挡、错页和首屏无元素场景能够自动修正。
- 全程没有触发任何改变业务数据的操作。
- 失败时 UI 能说明尝试过的路径、失败分类和人工处理建议。

## 发布策略

1. 先在开发环境启用多轮探索并记录命中率、平均轮次和失败分类。
2. 与当前单轮策略进行同批测试点对比。
3. 达到稳定阈值后默认启用，保留项目级开关回退到单轮模式。
4. 对探索超时、误导航和 Locator 失败持续更新评分词典和页面知识，不扩大危险动作白名单。
