# Agent 式 Web 用例生成与 Agent 资产设计

## 1. 背景与目标

当前 Web 用例生成以一次性结构化请求为主。模型需要在一次响应中同时完成需求理解、页面定位、步骤生成、断言生成和 JSON 格式化，容易出现超时、猜测 locator、缺少断言、输出截断和批次结果丢失。

本设计将生成流程改为可恢复的阶段门控 Agent 任务：每个阶段有明确输入、允许工具、输出结构、确定性校验和失败处理。用户可以看到安全的流式执行摘要，最终只有完整且通过校验的用例进入现有评审和保存/执行流程。

本设计同时新增三类可维护 Agent 资产：

- 可版本化的全局 `AGENT.md` 与六个阶段规则。
- 按项目、环境、模块和页面分组的页面元素定位知识库。
- 生成成功后产生、人工确认后生效的经验记忆。

## 2. 已确认的产品决策

- 采用阶段门控 Agent，而不是自由多轮黑盒 Agent。
- 默认自动推进全部阶段；不自动运行最终 Web 用例。
- 保留现有主流程：需求导入 → AI 生成 → 评审 → 保存/执行。
- AI 生成阶段增加 Agent 工作区和流式面板，不改主页面阶段结构。
- Agent 资产入口位于 AI 设置中的“Agent 资产”总览仪表盘。
- 经验记忆默认项目隔离，人工确认后可以提升为全局，并可随时调整作用域。
- 页面 locator 知识始终绑定项目、环境、模块和页面，不能跨环境直接复用。
- 流式面板默认显示摘要；详细输入和结构化输出通过脱敏侧滑抽屉查看。
- 不显示模型隐藏推理过程，只显示可审计的输入摘要、工具动作、输出摘要和校验结论。

## 3. 阶段门控流程

每次任务启动时固化全局规则版本、阶段规则版本、项目范围、运行环境和任务输入摘要。运行中的规则不可变更。

### 3.1 环境预检

输入：项目、Web 运行环境、AI 主路由、已确认测试点范围。

允许动作：读取 AI 就绪状态、读取 Runner 健康状态、读取已发布规则和能力配置。

禁止动作：调用模型、采集页面、写入用例。

通过条件：主路由可用、Runner 可用、Base URL 合法、浏览器可启动、规则版本完整。

失败行为：任务进入 `blocked`，流式日志说明缺失项，提供跳转到配置或运行环境的入口。

### 3.2 证据取用与浏览器取证

首轮 Agent 只输出每个测试点的目标页面和访问意图，不输出 locator，不生成最终 DSL。

服务端调用 Web Runner 访问目标页面，采集页面 URL、可见元素、稳定 locator、角色、可访问名称、元素类型、页面指纹和采集时间。登录流程使用当前环境配置，不把账号密码写入事件或知识库。

通过条件：每个可生成测试点都有可访问页面和可用页面证据；没有证据的测试点进入阻塞列表，不允许猜测 locator。

### 3.3 用例规划

Agent 基于测试点、阶段规则和浏览器证据生成结构化计划：测试目标、页面、用户动作意图、需要验证的结果和证据引用。此阶段不写最终步骤文本，locator 使用证据 ID 引用。

通过条件：每个请求测试点有一个计划；计划包含可执行目标和至少一个可验证结果。

### 3.4 分点生成

按测试点逐条或小批次生成完整 Web DSL。每个动作必须是 Runner 支持的动作；所有 click/input/select/hover/wait/assert locator 必须来自当前批次浏览器证据；每个用例的 `steps` 必须包含可执行断言。

生成结果先进入 Agent 任务的工作区，不直接覆盖最终用例列表。每个通过校验的测试点可以作为完整结果追加，保留现有分批恢复能力。

### 3.5 确定性校验与修复

服务端依次校验 JSON 结构、必填字段、DSL 动作、URL、locator 格式、locator 证据白名单、断言动作、测试点覆盖和重复 ID。

校验失败时只将明确错误交给 Agent 修复，并保留原始候选和修复轮次。修复次数达到上限仍失败时，测试点标记为阻塞并保留错误原因，不将不完整结果写入最终列表。

### 3.6 持久化与交付

只有通过全部校验的完整用例才进入现有生成列表和草稿持久化。任务保存规则快照、证据引用、检索命中、每轮摘要、校验结果、最终用例和阻塞项。

完成后自动生成一条短经验候选，进入“待确认记忆”，不自动影响后续任务。用户确认后才成为有效记忆。

## 4. Agent 规则资产

### 4.1 文件和版本

根目录维护全局 `AGENT.md`，包含安全边界、证据优先级、敏感数据处理、工具使用约束和输出基本契约。六个阶段规则单独维护，分别对应预检、取证、规划、生成、校验、持久化。

AI 设置 → Agent 资产 → 全局规则中支持：

- 编辑草稿、发布新版本、查看历史、差异比较和回滚。
- 查看六个阶段规则的完整性和发布状态。
- 发布前执行格式、必填章节和危险指令检查。

任务只读取已发布版本。项目级规则只能追加限制，不能覆盖全局安全规则。

### 4.2 运行快照

任务创建时记录 `agentRulesVersion`、阶段规则版本、内容摘要和发布时间。流式面板展示摘要和版本号，详情抽屉可以查看脱敏后的具体规则。

## 5. 页面元素定位知识库

### 5.1 数据分组

层级固定为：项目 → 运行环境 → 业务模块 → 页面 → 元素。

元素记录至少包含：自然语言名称、模块、页面 URL、页面指纹、locator、角色、可访问名称、元素类型、采集来源、采集时间、最后验证时间、当前状态和证据版本。

### 5.2 采集和更新

Web 自动化页面保留“采集当前页面并更新知识”快捷入口；AI 设置 → Agent 资产 → 页面元素知识库提供总览、模块树、搜索、失效标记、重新采集和历史版本。

重新采集使用当前 Web 运行环境和浏览器，不允许手工输入 locator 作为已验证证据。页面指纹变化或验证失败时，旧元素标记为 `stale`，不再作为生成证据。

### 5.3 检索策略

Agent 根据测试点标题、目标、模块、页面和动作意图检索相关元素，返回元素 ID、自然语言描述、locator、页面指纹和可信度。第一版采用模块/页面过滤加结构化关键词检索，并预留 embedding 检索接口；检索结果只是候选知识，写入用例前必须由当前浏览器重新验证。

## 6. 经验记忆

每次完整成功的生成任务产出短文本候选，类别包括成功经验、失败原因、平台习惯、locator 注意事项和数据准备方式。每条记忆关联来源任务、项目、模块、阶段、规则版本、创建人和创建时间。

记忆默认作用域为当前项目。人工确认时可以选择：当前项目、指定项目集合或全局。确认、编辑、禁用和删除都保留操作记录。只有状态为 `active` 的记忆可以被 Agent 检索；待确认记忆只展示在确认队列，不参与生成。

## 7. 流式 Agent 工作区

AI 生成阶段保留现有生成范围、进度、结果表和按钮，在进度区域下增加 Agent 工作区：

- 顶部：当前阶段、任务状态、规则版本、已完成测试点和阻塞数。
- 中部：按时间追加的输入摘要、Agent 动作、工具结果、输出摘要和校验结果，默认自动滚动，用户向上查看历史时暂停自动滚动。
- 右侧侧滑：查看当前阶段的脱敏输入摘要、知识命中项、结构化候选输出、修复前后差异和校验错误。
- 底部：终止任务、重试当前阶段、跳到阻塞项和查看完整任务记录。

生成中的候选不会污染最终用例表；通过校验的完整测试点可以增量进入列表，刷新或失败后可从任务记录恢复。

流式事件只包含可审计字段：阶段、摘要、状态、测试点 ID、工具名、耗时、规则版本、知识命中 ID和错误码。禁止写入 API Key、密码、Cookie、完整敏感文档和隐藏模型推理。

## 8. 失败与恢复

- AI 服务超时：保留任务和已完成测试点，从当前阶段重试，不清空最终列表。
- Runner 不可用：预检阶段阻塞，不发起模型生成。
- 页面指纹变化：重新取证；旧 locator 标记失效。
- 证据不足：请求人工补充页面、模块或登录环境，不允许模型猜测。
- 结构化输出失败：进入有限修复轮次；超过上限后保留完整错误上下文。
- 用户终止：保存已完成结果和未完成测试点，允许继续任务。

## 9. 验证范围

后端测试覆盖：阶段状态机、规则版本快照、任务恢复、locator 知识分组与失效、检索结果白名单、记忆确认与作用域、敏感字段脱敏、流式事件顺序、校验失败和分批追加。

前端测试覆盖：Agent 工作区阶段状态、日志自动滚动、暂停滚动、详情侧滑、终止与恢复、知识库模块树、记忆确认队列、规则编辑发布和版本回滚。

验收标准：任何最终写入的 Web 用例都具备完整字段、至少一个可执行断言、所有 locator 都有当前浏览器证据，且能从任务记录追溯规则版本、证据来源、校验结果和人工记忆作用域。
